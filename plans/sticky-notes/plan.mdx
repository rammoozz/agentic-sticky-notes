# Sticky notes Claude pins while it works

## What you see

You tell Claude *"keep JWT, no sessions table. Rate limiting can wait. Staging db is read-only."* and keep talking. Claude calls `note_add` three times as it goes, and three colored notes show up in a **Sticky notes** pane beside the chat (see the canvas): a green **decision**, a yellow **todo**, and a blue **remember** that only matters in this chat. Forty minutes and one `/compact` later, Claude still knows all three, because the open notes are fed back to it when the session starts or compacts. When it finishes the rate limit work, it marks that todo done.

The same notes are plain files on disk. From any terminal, `sticky ls` prints them and `sticky done n_k3f9x` checks one off; the pane picks that up within 3 seconds. The MCP server also works in other MCP apps (Claude Desktop, Cursor), where you get the tools without the pane.

## Done means

- Claude pins a **human** note whenever it needs you (a choice only you can make, a login or key, an approval, a manual step), sends a terminal notification for it, and keeps going with a safe default when it can. Each person sets their own rule for when to pin in `/config`.
- Claude also pins notes on its own, without being asked, when a decision is made, a rule or preference is stated, work is pushed to later, or a question is left open. It also pins on "note that", "remember", "don't forget".
- A note shows in the pane within a second of `note_add`, and within 3 seconds of a change made from the CLI or another session.
- **Project** notes show in every session in that repo. **Chat** notes show only in the chat that pinned them. Claude picks per note.
- After `/compact`, `/clear`, a resume, or a new session, Claude's context starts with the open notes that apply.
- `sticky add | ls | done | edit | rm` works from any terminal, and `sticky ls --json` prints the same notes the pane shows.
- Two sessions and the CLI writing at once never lose a note or leave a broken file. Two edits to the same note at the same moment: the last one wins.
- If mods break or are off, the MCP tools, CLI, skill and context hook all still work. Only the pane goes away.
- `npm run check` (strict `tsc`, tests, build) and `claude plugin validate . --strict` pass.

**Not in scope:** floating desktop note windows, sync across machines, sharing, typing or editing notes inside the pane, drag to reorder, rich text, a board for every project at once.

## Approach

<Callout tone="decision" title="One plugin: MCP + CLI + skill write the notes, a thin mod only draws them">
The repo is one Claude Code plugin named `sticky-notes`. All the real logic lives in one small TypeScript core (`src/`) that reads and writes one JSON file per note. Three doors use that core: the **MCP server** (Claude's tools, in any MCP app), the **`sticky` CLI** (you, scripts, Claude via Bash, and the context hook), and the **skill** (tells Claude when to pin). The core is bundled into one file, `dist/sticky.js`, so the plugin needs no `npm install` after it is installed.

Mods are new, so the mod (`hooks/pane.ts`) does only three things: it draws the pane, it adds a `/notes` command, and it stamps the live session id onto note tool calls. It never touches files. It reads and writes through the plugin's own MCP server with `$.mcp.call`, so there is exactly one code path for notes. Mods can call MCP and run CLIs, so nothing here is Claude Code only except the pane.
</Callout>

<Columns>
<Column label="Tools from MCP, pane from a mod (chosen)">
Claude's tools come from a normal MCP server, so they work in Claude Code, Claude Desktop, Cursor and anything else that speaks MCP. The mod is a view on top. If a Claude Code release changes the mods API, only the pane breaks.

## Choices that are hard to change later

These are what other code, permission rules and saved files will depend on, so they are fixed now.

| Choice | Value | Why |
| :- | :- | :- |
| Plugin / server / tool names | plugin `sticky-notes`, server `notes`, tools `note_add`, `note_list`, `note_update`, `note_delete` | Claude Code names them `mcp__plugin_sticky-notes_notes__note_add`. Permission rules, the skill and the mod matcher all use that name. |
| Note id | `n_` + 5 lowercase base36 chars, e.g. `n_k3f9x` | Short enough for you and Claude to type in `sticky done`. Retry on the rare clash. |
| Where notes live | `~/.sticky-notes/<project-key>/<id>.json`, with `STICKY_NOTES_HOME` to move it (tests use it) | Outside the repo, so nothing shows up in `git status`. Key = project path with non-letters/digits turned into `-`, the same way `~/.claude/projects/` names folders. |
| What "project" means | git root of `CLAUDE_PROJECT_DIR` (MCP, hooks) or of cwd (CLI); the folder itself outside git | One rule for every door, so Claude started in `src/` and `sticky` run from the repo root see the same board. |
| Note shape | `v: 1` plus the fields in `src/types.ts` below | `v` lets a later shape be read side by side with old files. |
| Chat notes | `scope: "chat"` + `session` = Claude Code session id | Session ids come from `CLAUDE_CODE_SESSION_ID`, which Claude Code sets for Bash, hooks and MCP servers. |

<Callout tone="warn" title="The MCP server's session id goes stale">
Claude Code docs: an MCP server process "retains the ID it was spawned with", so after `/clear` (and sometimes `--continue`) its `CLAUDE_CODE_SESSION_ID` is the old chat's id. Bash and hooks get the new id. The mod fixes this by stamping `session: $.session.id()` onto every note tool call before it runs. Without the mod (other MCP apps, mods off), chat notes pinned after `/clear` land on the old id and only show in `sticky ls --all`. Project notes are not affected.
</Callout>

import { mkdir, readdir, readFile, rename, writeFile } from 'node:fs/promises'
import { homedir } from 'node:os'
import { join } from 'node:path'
import { NoteSchema } from './note.ts'
import type { Note } from './types.ts'

const HOME = process.env.STICKY_NOTES_HOME ?? join(homedir(), '.sticky-notes')

export function projectRoot(dir: string): string {
  try {
    return execFileSync('git', ['rev-parse', '--show-toplevel'], { cwd: dir, encoding: 'utf8' }).trim()
  } catch {
    return dir // not a git repo: the folder is the project
  }
}

const folder = (project: string) => join(HOME, project.replace(/[^A-Za-z0-9]/g, '-'))

async function save(note: Note): Promise<Note> {
  const dir = folder(note.project)
  await mkdir(dir, { recursive: true })
  const file = join(dir, note.id + '.json')
  await writeFile(file + '.' + process.pid + '.tmp', JSON.stringify(note, null, 2))
  await rename(file + '.' + process.pid + '.tmp', file)
  return note
}

async function readNote(file: string): Promise<Note | null> {
  try {
    const parsed = NoteSchema.safeParse(JSON.parse(await readFile(file, 'utf8')))
    return parsed.success ? parsed.data : null
  } catch {
    return null
  }
}

export async function listNotes(project: string, session: string | null, includeDone: boolean): Promise<Note[]> {
  const dir = folder(project)
  const names = (await readdir(dir).catch(() => [] as string[])).filter((n) => n.endsWith('.json'))
  const notes = (await Promise.all(names.map((n) => readNote(join(dir, n))))).filter((n): n is Note => n !== null)
  return notes
    .filter((n) => (includeDone || !n.done) && (n.scope === 'project' || n.session === session))
    .sort((a, b) => a.createdAt.localeCompare(b.createdAt))
}

## Steps

- [ ] **0. Check the new mods API (short spike).** Scaffold the manifest, an empty `hooks/pane.ts` and `hooks/hooks.json`, then run `claude --plugin-dir .`. Read the types Claude Code writes to `.claude-plugin/types/claude-code/index.d.ts` and confirm: the `$.mcp.call` signature and result shape, whether `$.session.id()` is sync, that MCP tool args are fields of `e` on `tool.call`, and the setting that keeps the `notes` server out of tool search (docs: mcp "exempt a server from deferral"). Fix the `pane.ts` sketch above to match before step 6.
- [ ] **1. Core.** `src/types.ts`, `src/note.ts`, `src/store.ts`, with `src/store.test.ts` covering: add/list/update/delete, chat notes hidden from other sessions, git subfolder maps to the repo root, a broken file is skipped, 20 parallel adds keep 20 notes.
- [ ] **2. CLI.** `src/cli.ts` with `parseArgs`: `add <text> [--kind] [--chat]`, `ls [--all] [--json]`, `done <id>`, `edit <id> <text>`, `rm <id>`, `context`, `mcp`. Session from `CLAUDE_CODE_SESSION_ID`. `npm run build` → `dist/sticky.js` with a `#!/usr/bin/env node` banner. `bin/sticky` shim, `package.json` `bin` for `npm link`.
- [ ] **3. MCP server.** `src/mcp.ts` with the 4 tools. Try it with `npx @modelcontextprotocol/inspector node dist/sticky.js mcp`.
- [ ] **4. Context hook.** `sticky context` reads the hook's stdin JSON, prints the notes, exits 0. Wire it in `hooks/hooks.json`.
- [ ] **5. Skill.** `skills/note/SKILL.md` as above.
- [ ] **6. Pane mod.** `hooks/pane.ts`, `types/index.d.ts`, `hooks/pane.test.ts`. Run the pane look through `/frontend-design` and `/critique` before calling it done.
- [ ] **7. Ship.** `plugin.json`, `marketplace.json`, `README.md` (install, other MCP apps, the Claude Code version it was tested on: 2.1.309), `.gitignore`. `claude plugin validate . --strict`.

<Callout tone="warn" title="Risks">
- **Mods are new.** Events and methods can change between releases. The mod holds no logic, so a break costs the pane only. The README names the tested version.
- **Auto-opened panes need room.** Claude Code only places a pane the user didn't ask for from 144 columns wide (110 once they've opened it before). In a narrow terminal the user opens it with `/notes`.
- **Polling.** The pane calls `note_list` every 3 seconds. That reads a few small files, but it is still a timer. It is the only way to see CLI edits, since mods can't watch files.
- **Committed bundle.** `dist/sticky.js` must be rebuilt before each commit, or installs run old code. `npm run check` runs the build.
- **Note spam.** If Claude pins too much, the board turns into noise. The skill caps 2 per turn and asks for update over add. Tune the wording after a week of use.
